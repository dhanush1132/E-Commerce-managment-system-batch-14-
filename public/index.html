Relational Business Rules

Customer → Order (1 : M)

A customer can place multiple orders; each order belongs to one customer.

Category → Product (1 : M)

A category can contain multiple products; each product references one category.

Order → Order_Item (1 : M)

An order can contain multiple line items representing individual purchased items.

Product → Order_Item (1 : M)

A product can appear in multiple order items across different orders.

Order → Payment (1 : 1)

Payment details are strictly linked to an individual order via FK Order_ID.

Order → Delivery (1 : 1)

Delivery fulfillment information is tied to an order with unique status tracking.

Database Management System Project

E-Commerce Management System

Relational database architecture for organizing, managing, and maintaining integrity across modern online shopping systems.

Department of Computer Science & Engineering Under the Supervision of Mr. K. RAJENDRA

The Problem Addressed

"How can an e-commerce platform organize its data so that customer, product, order, payment and delivery information remains connected, accurate and easy to retrieve?"

1. Data Duplication

Eliminated via 3NF normalization.

2. Disconnected Records

Linked by strict Foreign Keys.

3. Difficult Retrieval

Fast querying with indexed tables.

4. Data Integrity

Protected with CHECK & NOT NULL.

Key Project Objectives

  • 1 Structured Database: Design a clear relational model for e-commerce operations.
  • 2 Data Management: Efficiently organize customers, products, orders, payments, deliveries.
  • 3 Integrity: Use PKs and FKs to maintain valid and referential relationships.
  • 4 Low Redundancy: Reduce unnecessary duplication through structured design.
  • 5 Easy Retrieval & Scalability: Support fast multi-table queries and an extensible foundation.
